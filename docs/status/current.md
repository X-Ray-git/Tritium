# 当前状态

## 已确定

- 主导航：推荐、热榜、设置。
- 详情支持问题、回答、文章、想法、评论和用户公开资料。
- 所有远端交互保持只读，回复采用单层弹层查看；根评论内的缩略跟评会直接解析并
  加载知乎表情，同时保持两行省略，普通图片附件仍只在完整评论视图中展示。
- 评论区划到尾部会自动加载下一页：评论组件在列表末尾放一个哨兵，滚动接近底部或
  哨兵进入预加载范围时自动拉取下一页，尾部保留“查看更多评论”作为兜底与可访问
  入口，加载失败时退化为“点击重试”。祖先滚动位置与哨兵使用同一滚动坐标系，
  重复/空分页会停止且评论按 ID 去重。
- 固定品牌色和显式明暗主题已建立。
- 推荐预加载保留分页游标，列表请求具有刷新代次与加载锁。
- 推荐流按稳定内容身份执行当前会话去重；刷新只替换为本会话新内容，全重复时保留
  原列表，空新增页和重复游标会停止。推荐页只在前台停滚后上报实际可见的回答、文章
  和问题，点击时上报已读；未知卡片不猜测参数，记录不跨进程持久化。
- 详情请求会复用同一内容的在途 Future，避免预加载和页面同时重复请求。
- 用户回答与文章已支持独立分页、错误重试和旧请求失效。
- 回答支持横向分页切换与中线触觉反馈；短正文无需额外滚动即可触发评论预加载。
- 正文图片支持同文画廊、双击和双指缩放、缩放后平移、左右翻图与长按操作。
- 正文图片不再继承 `<figure>` 的固定横向留白；新版 Logo 已生成 Android 启动图标
  和 macOS 风格 README 展示图。
- 主导航已跟进 Fourier（原 Auto Folo）当前样式：连续圆角玻璃表面、双层阴影、无选中胶囊，
  选中状态使用品牌色图标与轻微缩放；玻璃边缘包含 Fourier 同款方向性高光和
  内外两组阴影。
- Android 图标已与 Fourier 对齐为纯静态 `mipmap`：完整 Logo 只做无内边距
  圆角裁剪，不再生成会触发启动器蒙版安全区和二次缩放的 Adaptive Icon。
- Android 支持从 `zhihu://`、知乎 HTTPS 链接冷启动或运行中唤起；支持的内容进入
  原生阅读页，其余知乎内容和视频由系统浏览器兜底。
- 文章、回答和想法具有正文进度条及本地位置恢复；正文末尾到达视口下边缘即为
  100%，不足一屏的正文直接满格且不可拖动，评论不计入正文进度。长正文可沿顶部
  24dp 隐形触摸区域横向拖动定位，拖动时显示百分比。
- 文章和回答的长正文保留后台解析与语义分块，但改为一次布局全部正文块，避免多图
  内容在滑动时才创建新块、修正正文终点并造成进度条跳动。
- 本地阅读历史覆盖问题、回答、文章、想法和用户，支持打开、单项删除与清空，且不
  同步知乎服务器。
- 主要详情页统一提供分享、复制链接和浏览器打开。
- 下拉刷新复用 Fourier 受控维护的状态机，反悔收回边界与 AppBar 对齐。
- 登录页具备仅 Debug 生效的安全检查点，并对缺失结束回调和 12 秒加载超时兜底。
- 工程维护文档已按产品、架构、操作、状态和历史建立知识地图。
- 发布脚本已在临时 Git 仓库完成版本递增、提交和 annotated tag 验证。
- 统计值语义统一为可空解析：浏览量优先 `visit_count`、兼容 `read_count`，
  字段缺失/解析失败/尚未加载一律显示 “—”，绝不伪装成 0；热榜不再把眼睛图标
  绑定到 `follower_count`，热度改用 `metrics_area.text`/`detail_text`，回答数
  使用 `answer_count`，并支持 `image_area` 圆角缩略图与 `label_area` 新/热标签。
- 应用内链接重做为三层结构：URL 归一化（协议相对、站内相对、`link.zhihu.com`
  解包与循环防护、拒绝不安全 scheme）、类型化解析（question/answer/article/pin/
  people/org/appview/oia/zvideo 及 `zhihu://` 单复数）与统一导航策略；HTML 普通
  链接保留 flutter_html 嵌套结构、样式与选择能力，评论“查看图片/动图”仍用专用
  缩略图扩展，`#anchor` 页内定位，无 href 的文字不伪装成链接。
- 正文渲染对齐 Fourier：行内代码用 alphabetic baseline 的半透明圆角胶囊，
  整行代码块为单容器（8px 圆角、细边框、横向滚动、复制按钮带 1.2 秒勾选态），
  引用块、表格横向滚动、列表、分割线与正文图片样式统一；回答、文章、问题描述、
  想法和评论正文支持系统文本选择，且不破坏链接点击、图片交互、纵向滚动与回答横滑。
- 统一反馈入口 `TritiumFeedback`（info/success/warning/error 顶部胶囊，滑入淡入、
  不拦截交互）接管全部状态反馈；`Get.snackbar`、`SnackBar` 与仅状态用的
  `SmartDialog.showToast` 已迁移，图片保存成功使用与 Fourier 一致的成功动画。
- 评论图片缩略图、热榜缩略图与正文图片统一 8px 圆角且占位/错误态同裁切范围；
  专栏封面优先使用接口宽高；字段缺失时先用 5:3 稳定占位，图片解析完成后再按
  实际比例显示。接口请求已补充宽高字段，动态比例仅作为上游缺失时的兼容路径。
- 首页推荐/热榜/设置改为跟手的 PageView 横滑切换：三页显式保活、底部导航动画
  切页、`onPageChanged` 同步导航与标题、重复点击当前导航仍滚回顶部、离屏页面
  暂停动画（保留状态）；设置页 Switch 等横向控件不被主页抢走手势。
- 回答横滑分页由回答页接管：从问题页接收 ID 列表、`nextUrl` 与排序方式作为
  种子，距列表末尾约 2 项预取下一页；单回答入口先补齐所属问题第一页并保留当前
  回答；ID 去重、重复 cursor/空页/`is_end` 停止、失败可重试、追加不跳页，加载
  占位页不触发“已切换回答”的振动。
- Feed 通用卡片没有有效 URL 时不保留空 InkWell；无法识别的 feed envelope 在
  Debug 记录关键字段且不猜测成回答/文章导航。
- 根评论中的缩略跟评卡片与楼中楼弹层固定占满安全内容宽度，不再由短评论文字、
  加载态或错误态反向决定横向尺寸。
- 问题正文中的问题链接允许继续压入另一个问题详情页；显式关闭 GetX 仅按
  `/question` 路由名执行的重复拦截，避免不同 `questionId` 被静默忽略。

## 已知外部风险

- 知乎私有接口和登录流程可能随上游变化，偶发加载失败不一定能由客户端完全消除。
- 登录依赖 WebView Cookie；上游风控或页面结构变化可能影响成功率。
- 知乎 `link.zhihu.com` 跳转与统计字段（`visit_count`/`read_count`/热榜
  `metrics_area` 等）可能随上游调整；客户端已做可空解析与跳转循环防护，字段
  变化只会让指标显示 “—” 或跳转失效，不会崩溃。

出现问题时应先记录具体页面、网络错误和是否登录，再判断是页面状态机、接口字段
变化还是上游限制。日志不得包含 Cookie、签名或完整登录 URL。

除 `device-acceptance.md` 中的项目外，当前没有已知的真机前阻塞项。
